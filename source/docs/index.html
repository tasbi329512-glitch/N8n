Getting started

Create an account, connect your first app, and run a template in under ten minutes. The canvas has three building blocks: triggers start workflows, nodes do work, and connections carry data between them. Click any node to see live data from your last run.

Executions & billing

One execution = one run of a workflow, regardless of step count. Editor test runs are free. When you exceed your plan's quota, extra executions are billed at the overage rate shown on the pricing page — we'll warn you at 80% and 100% first.

Self-hosting guide

Run the Community Edition anywhere Docker runs:

docker run -d --name flowmint -p 5678:5678 flowmint/flowmint

Mount a volume for /data to persist workflows and credentials. For production, use the Compose file with Postgres and Redis, put it behind TLS, and set FM_ENCRYPTION_KEY. Kubernetes manifests are provided for larger installs.

Model context protocol

Any workflow can be exposed as an MCP tool: enable "MCP server" on the workflow, and models can discover and call it with typed inputs. Conversely, the MCP Client node lets your agents call external MCP servers — databases, file systems, and third-party tools — with credentials managed in the vault.

RAG pipelines

The standard pattern: a scheduled workflow ingests documents, chunks them, and upserts embeddings into your vector store. Agent workflows then retrieve relevant passages before answering. Keep the ingestion workflow on a schedule so answers stay fresh as docs change.

Custom nodes

Package any API as a native node with the Node SDK: declare operations and credentials once, and the builder generates the UI. Publish to your team library or share with the community.
